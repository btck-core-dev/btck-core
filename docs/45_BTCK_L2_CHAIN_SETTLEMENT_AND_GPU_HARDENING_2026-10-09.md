# BTC-K L2 链上结算与 GPU 执行加固记录（2026-10-09）

## 1. 结论

本轮已经完成 L2 正式启用前的**代码级最小闭环**，但没有启动生产 L2、没有加载正式 L2 金库私钥、没有开放提现或销毁 HTTP 接口，也没有影响当前 L1 MAINNET 节点、矿池或矿机。

完整回归结果以当前提交的测试报告为准；本轮继续加入链故障、磁盘故障、确认深度与重组恢复覆盖。

## 2. 已完成

### 2.1 按 L1 高度自动判定年份

- 唯一输入为节点 `getInfo.dag.virtual_blue_order_length - 1`。
- 高度 `1..31,536,000` 为 Year 1，之后每 `31,536,000` 块进入下一年；Year 4 后继续使用 Year 4 L2 分配矩阵。
- 生产结算必须连接指定 ChainId 的权威 L1 RPC；缺少 RPC、ChainId 不一致或高度无效时 fail closed。
- 手工年份仅保留为显式单元测试参数，现场 GPU 演示脚本也改为由 `BTCK_L1_HEIGHT` 推导年份。

### 2.2 真实链上充值

- 每张发票生成唯一 `(R, P)` 一次性隐身输出，并绑定付款 Agent、金额、请求体、nonce 和资源路径。
- 回执必须包含真实 `txid:vout`；Agent 使用其地址内的 spend key 对发票、outpoint、金额和 nonce 签名。
- 网关从权威 L1 节点验证：输出存在于 canonical UTXO、金额完全一致、输出与发票完全一致、达到确认数且未被认领。
- 发票、已认领 outpoint 和余额均持久化；进程重启后不能重复入账。
- 旧版“仅凭自签回执给内部余额充值”的路径已经移除。

### 2.3 提现

- `L2ChainBridge` 只接受真实付费余额，不接受 sandbox voucher。
- 提现 ID 持久幂等；余额先 reserve，再签名和广播。
- 广播前失败自动退款；签名后广播结果未知时保留相同交易等待查询，禁止猜测失败并生成第二笔交易。
- 桥只允许花费已被网关确认入账的 L1 outpoint、显式可信启动资金和自身已确认找零；不会误花发送到同一金库的未入账资金。
- 组件目前没有公开 HTTP 路由，防止未完成审批策略前被调用。
- `BROADCAST` 状态会持续用同一个交易 ID 对账；浅确认不会提前完成，交易从链和内存池消失时只重播原签名交易，不重新扣款或另造交易。
- 节点超时、ChainId 错误、非法高度或 UTXO 查询失败若发生在签名前，预留余额和销毁费用会自动退回。

### 2.4 可验证销毁

- 域分离字符串：`BTC-K/v2.4/L2/PROVABLE-BURN`。
- 使用确定性 hash-to-curve NUMS 点，不发布、生成或保存对应离散对数私钥。
- 冻结输出：
  - `R = 03954dd9940171c8509c2f2c796802f9e410bde80dd79f9bea69db30a964c39038`
  - `P = 03fb85216614cdf67a059c7c3128a788207d3320aa426d535cfd7a12c9e2c4aaee`
- 销毁金额与链上交易 ID 持久关联；链上网络费必须由独立费用储备承担，不得从应销毁金额或其他四方份额中暗扣。

### 2.5 GPU 执行边界

- 生产 worker 注册必须由其 payout 地址中的 spend key 签名，时间窗为 5 分钟。
- 心跳必须由同一 key 签名，时间窗为 2 分钟。
- 每个任务带随机 challenge；结果绑定 task ID、challenge 和输出 SHA-256，并由被指派 worker 签名。
- 非任务 owner、空输出、重复完成和过期任务均被拒绝。
- 真实付费任务没有认证 GPU 结果时返回 503 且不扣费；只有不可提现的 sandbox voucher 可以使用本地模拟响应。

### 2.6 持久化与守恒

- 财务账本使用同目录临时文件、`fsync` 和原子 `os.replace`，避免写到一半形成可解析的残缺账本。
- 已存在账本损坏、负余额或销毁承诺超过累计销毁金额时拒绝启动，不允许静默建立空账本。
- 五方结算、发票、提现、销毁和幂等状态均进入同一持久账本。

### 2.7 金库进程隔离与 KCU 定价收敛

- 公网 AI 网关只配置 L2 金库的**公开隐身地址**和只读/提交 RPC，不需要也不应加载 spend/view 私钥文件。
- 金库钱包仅由独立结算操作加载；当前没有提现/销毁 HTTP 路由，因此公网请求不能触发签名。
- 服务目录以 KCU/1,000 units 表达，`1 KCU = $0.00010` 为公开参考服务价值；网关在报价时通过版本化 BTC-K 参考价换算 mSatK，并向上取整为链上发票所需的整数 SatK。
- 启动参考价 `bootstrap-fixed-v1` 固定为 `$0.05/BTC-K`，不是市场现价。外部动态价格预言机继续停用，直至多来源 TWAP、陈旧保护、变动上限和异常停机完成审计，并通过新的版本显式启用。
- 用户和 GPU 服务方只有一种 BTC-K 钱包。显示可在 BTC-K/SatK 间切换；提现低于 10,000 SatK 时继续累计，网络费由独立费用储备支付。
- 节点 `getTransaction` 现在按 canonical virtual-blue ledger order 查询，并返回账本高度和确认数；L2 到账、提现与销毁统一等待配置的确认门槛。

### 2.8 已执行的故障注入

| 故障 | 预期结果 |
|---|---|
| `getInfo` / `getUTXOSet` 超时 | 签名前退款，零广播 |
| ChainId 错误或高度非法 | fail closed，签名前退款 |
| `submitTransaction` 结果未知 | 保留唯一已签名交易，不退款、不二次构造 |
| 重组或 mempool 驱逐 | 重播完全相同的 txid，不重复扣款 |
| 确认深度不足 | 保持 `BROADCAST`，达到门槛后才 `CONFIRMED` |
| 磁盘满导致原子替换失败 | 进程报错停止，最后一份持久账本保持可恢复 |
| 恶意或错误 GPU worker | 身份、owner、challenge、结果签名任一不符即拒绝 |

## 3. 仍然阻止生产启用的项目

以下项目未完成前，`ai_payments` 和 GPU 市场功能必须保持关闭：

1. 在隔离 MAINNET 环境用极小金额完整执行充值、确认、推理、五方分账、提现、销毁和重启恢复。
2. 由持有人创建与个人/矿池/生态钱包完全分离的 L2 金库并离线保管恢复词；代码已经允许公网网关只持公开地址，正式密钥仍不得写入仓库、日志或网关环境。
3. 冻结提现限额、延迟、人工/多签审批、紧急暂停和费用储备补充规则。
4. 自动故障注入已经覆盖节点不可达/超时、错误链、非法高度、浅确认、重组/驱逐、磁盘满、重启、重复广播、worker 失联及恶意 worker；仍需在真实小额彩排中验证进程断电恢复。
5. 首发使用版本化 KCU 服务目录和明确标记的固定 BTC-K 启动参考价；未来启用动态价格源前必须完成多来源 TWAP、陈旧保护、上下限和停机规则并重新审计。
6. 冻结候选提交和可复现制品后，由项目之外的安全人员执行独立审计；内部 220 项测试不能替代独立审计。
7. 修复审计发现并重新执行完整回归和 MAINNET 小额彩排后，才能单独审批启用 L2。
