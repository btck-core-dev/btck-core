## 5. 抗女巫与防狙击开奖算法：未来随机信标 + XOR 几何距离测距

为杜绝传统抽奖机制中大矿工通过分拆千万级临时地址（Sybil Attack）刷高中奖率的作弊行为，BTC-K 采用基于密码学哈希空间的未来信标测距：

1. **蓄水期**：在周期内（如 43,200 块），所有出块矿工的有效区块哈希记录在链上；
2. **未来信标锁定**：周期结束后，强制等待 $100$ 个区块（约 100 秒确认），提取 $H_{end}+100$ 的区块哈希作为随机信标：
   $$H_{beacon} = \text{SHA256}(\text{BlockHash}_{H_{end}+100} \parallel \text{EpochIndex}_{uint64})$$
3. **异或测距**：遍历计算过去周期内所有区块哈希与未来信标的异或几何距离：
   $$\text{Distance}_i = \text{BlockHash}_i \oplus H_{beacon}$$
4. **极值胜出**：$\text{argmin}_i(\text{Distance}_i)$ 的出块区块独揽当期头奖。
5. **密码学与博弈论客观评析（落实审计报告29整改意见）**：
   * **每个有效候选区块机会严格均等**：在 256 位均匀哈希空间中，每个有效区块与未知未来信标的 XOR 距离分布完全一致，没有任何区块具有先验优势；
   * **统计学期望与有效算力成正比**：矿工或矿池的长期中奖期望正比于其生产的有效区块份额（若某矿池产出全网 40% 的区块，其获得大奖的数学期望即为 40%），本算法消除的是“地址作弊”，而非否定物理算力的贡献；
   * **免疫地址女巫攻击**：开奖仅以链上真实产生的出块哈希为候选样本，矿工拆分成 1 个还是 10,000 个接收地址，对中奖概率产生 0 影响；
   * **杜绝提前定向算块**：未来信标在出块窗口关闭 100 块之后才诞生，任何算力都无法在挖矿期间获知信标靶心；
   * **散户与 Solo 矿工暗标逆袭**：散户矿工即便只挖出 1 个有效区块，在与未来信标的几何测距中，同样拥有一发入魂直接命中全网最小距离的真随机机会！

3. **生产环境直接充值接口禁用（修复 C-03）**：`/v1/deposit` 在生产模式下默认关闭并返回 HTTP 403 Forbidden，禁止未鉴权的余额修改。
4. **复合幂等键绑定（修复 H-02）**：幂等缓存以 `agent_stealth_address:model:idempotency_key` 进行复合隔离，杜绝跨账户与跨模型请求碰撞。
5. **共识级整数 SatK 结算（修复 H-06）**：全系统废除浮点数计价，统一采用 uint64 整数 SatK，从根源杜绝浮点数精度截断漏洞。

### 9.2 网关输出的标准响应头矩阵
* `WWW-Authenticate`: `L402 invoice="..."`, currency="SatK", amount="...", address="..."
* `X-Payment-Address`: 收款隐蔽地址（`btck1s...`，防链上关联）
* `X-Payment-Amount`: 精准结算金额（严格以 uint64 整数 SatK 聪K 计价）
* `X-Payment-Token`: `SatK`
* `X-Payment-Invoice`: 单次专属账单唯一哈希（由网关注册表严格校验）
* `X-Payment-Network`: `BTCK-BlockDAG`
* `X-Payment-Expires`: Unix 过期时间戳

## 10. 具身智能与物理机器人分层代理钱包技术架构（实验性规范 Profile v2.2.0）

随着人形机器人（Tesla Optimus、Figure 02、宇树 Unitree）、无人送货车与自动充电桩等**物理具身智能（Embodied AI）**的大爆发，机器人在物理世界的自主支付面临残酷现实：**物理拆机逆向私钥、模型幻觉挥霍资金，以及物理活动轨迹关联分析**。

BTC-K 官方 SDK（`btck_agent.robot_wallet`）在 v2.2.0 中完成了全面安全重构。

### 10.1 核心架构四重护甲（Hardened Profile）

| 维度 | 传统公链做法 | **BTC-K 具身智能专用钱包规范 (v2.2.0 强化版)** |
| :--- | :--- | :--- |
| **密钥硬件飞地隔离** | 纯软件明文保存，或由公开参数推导私钥（C-02 隐患） | **硬件飞地内部真随机生成（Fixes C-02）**：`HardwareEnclaveInterface` 内部由芯片硬件安全高熵随机数生成私钥且**永不导出**，外部仅能获取公钥并请求飞地内部签名，不可通过主地址/设备ID逆向推导 |
| **默认拒绝与三重预算** | 默认放行消费，无严格限额（H-03 隐患） | **默认拒绝（Default-Deny）+ 三重硬预算（Fixes H-03 & H-06）**：无主人有效签名 Delegation Pact 时严禁支出；严格要求 uint64 正整数 SatK；实施并发互斥锁保护的单笔上限、单日限额与终身授权总上限 |
| **第三方独立验真凭证** | 假冒确认（无签名或未上链标称 settled） | **规范摘要 + Schnorr 独立验真（Fixes H-04）**：输出 `SIGNED_PREPARED` 预备凭据，包含完整规范摘要、一次性临时公钥与支付方公钥，物理设备（如充电桩）可离线独立验证签名有效性 |
| **物理行踪与隐私边界** | 使用固定地址或忽视元数据泄露（H-05 隐患） | **双密钥隐蔽地址（Stealth Address）与威胁模型披露（Fixes H-05）**：链上输出一次性公钥阻断收款方物理关联；明确披露点对点网络元数据（如 IP 地址）需结合 Tor/I2P 保护 |

### 10.2 开发者快速集成范例

```python
from btck_agent import BTCKWallet, DelegationReceipt, RobotDelegatedWallet

# 1. 主人冷钱包签发具有严格预算上限的 Delegation Pact (单日/终身限额 100 SatK)
master_wallet = BTCKWallet.generate()
delegation = DelegationReceipt.issue(
    principal_keypair=master_wallet.keypair,
    agent_id="unitree_go2_alpha",
    max_amount_satk=100,  # 整数 SatK
    allowed_services=["ev_fast_charge.v1", "toll_booth.v1"],
    duration_seconds=86400
)

# 2. 初始化机器人板载硬件代理钱包 (内部硬件安全飞地生成不可导出子密钥)
robot_wallet = RobotDelegatedWallet(
    robot_id="unitree_go2_alpha",
    master_address=master_wallet.address,
    machine_index=1
)

# 3. 绑定主人授权策略 (默认拒绝模式解除，激活 20 SatK 单笔硬上限)
robot_wallet.bind_master_policy(delegation, single_tx_limit_satk=20)

# 4. 机器人自主前往物理充电桩结算 (硬件飞地签名 + 隐蔽地址一次性输出)
receipt = robot_wallet.pay_physical_service(
    service_id="ev_fast_charge.v1",
    recipient_stealth_address="btck1s_charging_pole_77_...",
    amount_satk=12  # 严格 uint64 正整数 SatK
)

print("物理支付凭据已签署 (SIGNED_PREPARED):", receipt["status"])
print("第三方可独立验真公钥:", receipt["payer_spend_pub_hex"])
print("规范摘要哈希:", receipt["canonical_digest_hex"])
```
