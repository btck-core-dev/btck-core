Machine-native money for a useful compute economy.

Bitcoin K combines a proof-of-work BlockDAG settlement layer with a planned market for independently operated GPU inference. Consensus and useful compute remain separate: GPU service can never create new BTCK.

STATUS DISCLOSURE — L1 mainnet is operating in a private guardian phase. L2 inference, DEX routing and delegated agent wallets are roadmap systems and are not live products.

1. Monetary policy

Daily integer SatK quotas guarantee exact issuance without floating-point drift. From block 126,144,001 onward, subsidy is zero. Transaction fees are permanently split 50% to the immediate miner and 50% to Combo.

2. Proof-of-work consensus

Bitcoin K uses kHeavyHash proof of work, GHOSTDAG ordering and an adaptive difficulty adjustment targeting one block per second. Parallel valid work is represented in the BlockDAG rather than treated as a conventional single-chain race.

3. Reward allocation

Phase one allocates each subsidy as 80% immediate miner reward, 15% Combo reserve and 5% ecosystem reserve. The Combo share grows across later years under the canonical emission schedule. Combo drawings target a twelve-hour interval.

4. Guardian phase

The network begins under controlled guardian hashrate to reduce early-chain reorganization and majority-attack risk. The public checkpoint is block 271,828. Its final hash will be frozen and published with reproducible release material. This operational protection does not change the programmed supply rules.

5. Agent and GPU economy

The planned L2 connects three roles: L1 miners secure settlement; GPU providers offer model inference; agents and human clients buy individual jobs in SatK. Provider competition, receipts and verifiable benchmarks are intended to make cost and quality observable.

Delegated wallets are designed around explicit scopes, per-call limits, period budgets and expiration. Private keys remain client-side. These controls require further implementation and security review before production release.

6. Privacy and security

The current wallet implements dual-key stealth addressing. Privacy claims remain limited until independent review. The browser must never receive private viewing or spending keys for server-side custody. Consensus, wallet and accounting components will be released with hashes, build instructions, an SBOM and known limitations.

7. What is not live

  • Permissionless DEX or liquidity routing
  • HTTP 402 inference settlement
  • GPU provider proof, slashing or reputation
  • Production delegated agent wallets
  • Bridges or exchange adapters
